# Змінні середовища

Усі значення в репо замінено плейсхолдерами `{{NAME}}`. Імена плейсхолдерів = імена змінних середовища, які читає `core/config.example.js` → `createConfig(env)`.

У Cloudflare Worker кожну змінну задати як **secret**: `wrangler secret put NAME`. Навіть ID не є критичними секретами, але так усе лежить в одному місці й не потрапляє в git.

## Discord

| Змінна | Що це | Де взяти | Таємне? |
|---|---|---|---|
| `DISCORD_PUBLIC_KEY` | Публічний ключ застосунку, hex, 64 символи. Ним перевіряється підпис Ed25519 кожного запиту | Developer Portal → застосунок → General Information → **Public Key** | Ні, але без нього система не працює, а з чужим ключем приймала б підроблені запити |
| `DISCORD_APPLICATION_ID` | ID застосунку | General Information → **Application ID** | Ні. У логіці не використовується, потрібен лише для реєстрації slash-команди |
| `DISCORD_GUILD_ID` | ID Discord-сервера поду | Discord → режим розробника → ПКМ на сервері → Copy Server ID | Ні. Використовується лише для посилання на канал |
| `DISCORD_ALLOWED_CHANNEL_ID` | ID каналу, в якому дозволено виклик | ПКМ на каналі → Copy Channel ID | Ні |
| `DISCORD_ID_TRADER_1` … `_5` | Discord user ID кожного трейдера | ПКМ на користувачі → Copy User ID | Ні. **У поточній логіці не використовується**, лежить у конфігу як довідка |

## Bark

| Змінна | Що це | Де взяти | Таємне? |
|---|---|---|---|
| `BARK_SERVER_URL` | Базова адреса Bark-сервера без `/` у кінці, напр. `https://bark.example.com`. Запит іде на `${BARK_SERVER_URL}/push` | Власник існуючого сервера або адреса свого (див. docs/INTEGRATIONS.md) | Ні |
| `BARK_KEY_TRADER_1` … `_5` | Device key застосунку Bark на iPhone трейдера **для цього сервера** | Застосунок Bark → сервер → скопіювати ключ (частина URL після адреси сервера) | **Так.** Хто знає ключ і адресу сервера, може слати трейдеру критичні сповіщення |

## Трейдери (необов'язково, для 1:1 з продом)

| Змінна | Що це | За замовчуванням |
|---|---|---|
| `TRADER_KEY_1` … `_5` | Ключ трейдера N: `value` у меню. У проді — нікнейм у нижньому регістрі | `trader1` … `trader5` |
| `TRADER_NAME_1` … `_5` | Підпис трейдера N у меню і в «Сигнал надіслано: …». У проді — нікнейм | дорівнює ключу |

Номер N має збігатися з `BARK_KEY_TRADER_N` і `DISCORD_ID_TRADER_N`. Відповідність N → людина дає власник.

## Лише для n8n-експорту

Ці плейсхолдери є тільки в `n8n/workflow.json` і документах, у Worker вони не потрібні.

| Плейсхолдер | Що це |
|---|---|
| `{{N8N_BASE_URL}}` | Адреса інстансу n8n. Вебхук: `{{N8N_BASE_URL}}/webhook/pod-alert` |
| `{{N8N_WEBHOOK_ID}}` | Внутрішній `webhookId` ноди Webhook (n8n генерує новий під час імпорту) |

## Не зберігається ніде в системі

- **Bot token Discord** не потрібен для роботи: відповіді йдуть у відповідь на HTTP-запит interaction. Він потрібен лише один раз, щоб зареєструвати slash-команду `/trader` (див. docs/INTEGRATIONS.md).
